01The AI-era case for metadata

Metadata and lineage are becoming the context layer for AI

For a decade, data catalogs were built for humans: a searchable inventory that helped analysts find tables and helped stewards pass audits. In 2025–2026 the primary consumer changed. LLM applications and autonomous agents now need exactly what catalogs have always collected — schemas, semantics, ownership, quality signals, lineage — but delivered programmatically, in real time, at machine speed.

This shift has a name the industry has converged on: context management (or the "context platform"). The reasoning is simple. An LLM is only as trustworthy as the context in its window. Enterprises found that context quality, not context volume, is the limiting factor for production agents: an agent that cannot tell a certified revenue table from a deprecated staging copy will confidently produce wrong answers. The metadata graph — what each dataset contains, what columns mean, who owns them, how fresh and how trusted they are — is the antidote to that failure mode.

Why lineage specifically matters more, not less

  • Provenance for AI outputs. When an agent answers a question or a model makes a decision, lineage is the audit trail from the answer back through pipelines to source systems. Regulations (EU AI Act, model risk management in finance) increasingly require exactly this traceability for training data and features.
  • Impact analysis at machine speed. Column-level lineage lets both engineers and agents ask "if this column changes, what breaks downstream — which dashboards, which features, which agents?" before the change ships.
  • Trust scoring for retrieval. RAG and text-to-SQL systems use lineage-derived signals (certified upstream sources, passing quality checks, active ownership) to rank which assets an agent is allowed to reason over.
  • Automated governance. Classification (PII, confidential) propagates along lineage edges, so a policy set at the source follows the data into every derived table, dashboard, and now every AI feature store and prompt pipeline.
Mechanism of the shift

The Model Context Protocol (MCP), introduced by Anthropic in late 2024 and adopted across the industry, is the concrete plumbing of this change. Every major catalog — DataHub, OpenMetadata/Collate, Atlan, Collibra, Google's Knowledge Catalog, Databricks — shipped an MCP server in 2025–2026, letting agents in Claude, Cursor, Windsurf, or custom frameworks search assets, traverse lineage, inspect schemas, and check policies through one standard interface. The catalog UI is becoming just one client among many; the durable product is the governed metadata graph behind it.

Two more forces compound the shift. Unstructured data is entering catalog scope — PDFs, documents, embeddings, and vector stores need the same classification and lineage as tables, because agents consume them the same way. And data products / data contracts (machine-readable schemas, SLAs, and quality guarantees) are becoming the packaging unit that both humans and agents subscribe to, with the catalog enforcing the contract.

02The reference implementation

DataHub: from LinkedIn's WhereHows to a context platform

DataHub is the clearest single case study of how this category is evolving, because it has publicly reinvented itself three times — search tool, metadata platform, and now "The Context Platform for your Data and AI Stack."

2016 → 2019
WhereHows → DataHub at LinkedIn

LinkedIn replaces its crawl-based WhereHows catalog with DataHub, pioneering a stream-based, event-driven metadata architecture: sources push change events through Kafka into a graph + search index, so metadata is always fresh rather than periodically scraped.

2020 → 2021
Open source & commercialization

Open-sourced under the Linux Foundation umbrella of governance-neutral hosting; core team spins out as Acryl Data with a $9M seed to build DataHub Cloud (managed SaaS). Community adoption spreads to Expedia, Saxo Bank, Klarna, Etsy, and others.

Jan 2025
DataHub 1.0

Five-year anniversary release: 80+ production connectors, automated column-level lineage, data contracts, observability integrations, and a revamped UX — the "mature metadata platform" milestone.

2025
The MCP server

Official mcp-server-datahub ships: agents get entity search, schema and ownership retrieval, upstream/downstream lineage traversal, and query-to-dataset mapping over live metadata — with OAuth2 dynamic client registration for enterprise auth.

May 2026
DataHub Cloud v1 — the context platform

Repositioned as a context platform for analytics agents: the event-driven graph continuously syncs 100+ sources and exposes governed context (lineage + glossary + ownership + classification + docs) to MCP-compatible AI tools. Marketing follows engineering: "context, not catalog."

Where DataHub goes next

  • Agent-first surface area. The roadmap treats AI agents as first-class metadata consumers: LLM-friendly metadata serialization, MCP as a stable contract, and "context APIs" that return ranked, trust-scored context rather than raw records.
  • Real-time as the moat. DataHub bets that streaming metadata (versus batch-crawled snapshots) is decisive once agents act autonomously — a stale lineage edge misleads an agent instantly, at scale.
  • Governance automation. Policy-aware agents that enforce classification and access rules automatically, flag violations before they happen, and keep audit trails — governance as a continuously running process instead of a quarterly project.
  • The open-core tension. Advanced AI features and observability concentrate in DataHub Cloud, while the OSS core competes with a faster-moving OpenMetadata. Managing that split is DataHub's key strategic risk over 2026–2028.

03The commercial field

Where the commercial platforms are heading

Two distinct commercial species are converging on the same territory: platform-native catalogs (Google, Databricks, Snowflake, Microsoft) that govern their own engine first, and independent catalog vendors (Atlan, Collibra, Alation, Informatica) that federate across everything. Every one of them re-platformed around AI in 2025–2026.

Google Cloud Knowledge Catalog Platform-native

Formerly Dataplex Universal Catalog · renamed April 2026

Google's catalog has been renamed twice in three years (Data Catalog → Dataplex Universal Catalog → Knowledge Catalog), and the latest name is the strategy: a Gemini-powered context graph. It auto-harvests technical metadata from BigQuery, AlloyDB, Spanner and third-party systems, then uses Gemini to infer business intent from schemas, query logs, and semantic models — generating descriptions, discovering relationships, and proposing verified SQL patterns. It now profiles unstructured data (e.g. PDFs in Cloud Storage) to extract entities and relationships, and ships pre-built MCP tools so Gemini and third-party agents query the catalog directly.

The catalog as an anti-hallucination layer — "grounding AI agents in enterprise truth" is the stated product goal, not an add-on.

Databricks Unity Catalog Platform-native

Lakehouse governance · OSS'd June 2024

Unity Catalog governs the broadest asset range of the native catalogs: tables, files, notebooks, ML models, vector indexes, and AI agents/tools themselves, across workspaces and clouds. Databricks open-sourced the core and supports the Iceberg REST catalog API, positioning UC as a multi-engine standard rather than a walled garden. Its AI direction runs through the "Data Intelligence" thesis: automated documentation, semantic understanding of the estate, metric views as a governed semantic layer, and governance for GenAI assets (models, prompts, agent tools) alongside data.

Govern data and AI assets in one permission model; win by being where the compute already is.

Snowflake Horizon Catalog Platform-native

The "Data Cloud" governance layer + Polaris

Horizon extends Snowflake's built-in governance (tags, masking, row policies, Universal Search) beyond native tables to external Iceberg — even Delta tables — with policies enforced at the catalog layer. Via Apache Polaris (Snowflake-initiated, open source), any engine speaking the Iceberg REST spec can read and write under vended credentials with governance intact. AI direction couples Horizon to Cortex: agents and Copilot features inherit the same discovery, trust signals, and access policies the warehouse enforces.

Compete on openness at the table-format layer while keeping governance — and therefore gravity — inside the Data Cloud.

Microsoft Purview Unified Catalog Platform-native

Governance domains · data products · Copilot

Purview merged data governance with security/compliance into one control plane. The Unified Catalog organizes the estate into governance domains and subscribable data products, searched through an AI copilot. The 2026 direction is AI governance itself: cross-workload AI policies (define once, enforce across Copilot, GitHub, Power Platform), a federated catalog of approved models, and DSPM for AI — auditing what data Copilots and agents actually touch.

The catalog becomes the policy plane for AI usage across the entire Microsoft estate, not just a data inventory.

Atlan Independent vendor

"Context lakehouse" · MCP-native

Atlan moved from Visionary to Leader in Gartner's 2026 MQ on the back of an explicitly agent-first architecture: native MCP server, real-time metadata sync across 100+ connectors, and a GraphQL API agents query directly. Its 2026 "Context Lakehouse" frames the pitch: certified, governance-embedded context served to agents — not raw schema dumps.

Governed context first, agent capability second — the independent-vendor version of the DataHub thesis, sold as SaaS.

Collibra · Alation · Informatica Independent vendors

Governance incumbents retooling for agents

Collibra shipped an AI Command Center (May 2026) and an MCP server distributed through the Databricks Marketplace — its posture is governance and oversight of agents, not agent execution. Alation's Agent Builder went GA in Q1 2026, layering task-specific agents on its behavioral-intelligence catalog. Informatica (acquired by Salesforce, 2025) folds CLAIRE-powered metadata into Salesforce's agent stack — notably giving Salesforce Data Cloud an enterprise metadata backbone for grounding Agentforce agents.

The incumbents' bet: enterprises will pay for the control plane that supervises other people's agents.

Common thread

Every commercial roadmap converges on the same four moves: (1) an MCP or equivalent agent interface, (2) LLM-generated documentation and semantics at harvest time, (3) unstructured data and AI assets (models, prompts, agents) brought under catalog governance, and (4) the catalog repositioned as the grounding/trust layer that makes agents safe to deploy. The differences are about center of gravity — engine-native vs federated — not about direction.

Reading the field

  • DataHub remains the engineering-heavy choice: the event-driven architecture is genuinely harder to run, but it buys real-time metadata and the deepest lineage — and its MCP/context-platform work is the most production-proven in open source (see Block, §06).
  • OpenMetadata won the adoption race on simplicity: one schema, two databases, weekly releases, and quality checks in the box. Its "open context layer" positioning mirrors DataHub's almost word for word — the two projects have converged on the same AI-era thesis from opposite architectural starting points.
  • Apache Atlas and Amundsen illustrate the category's mortality: Atlas is bound to a shrinking Hadoop world, and Amundsen — briefly the most popular catalog of the early 2020s — has no future roadmap. Discovery-only tools didn't survive; governance-plus-context platforms did.
  • OpenLineage/Marquez plays a different game: OpenLineage is now the de-facto standard for pipeline lineage events (emitted by Airflow, Spark, dbt, Flink) and feeds catalogs rather than competing with them — both DataHub and OpenMetadata ingest it.

Choose OSS self-hosted when…

You have platform engineers, a heterogeneous or on-prem estate, data-sovereignty constraints, or need custom metadata models. DataHub for lineage depth and agent integration; OpenMetadata for fastest all-in-one time-to-value.

Choose managed open-core when…

You want the OSS model without running Kafka and Elasticsearch yourself — the pragmatic default for mid-size data teams, with an exit path the pure-commercial tools can't offer.

Choose commercial when…

Governance workflow, compliance reporting, and business-steward UX are the bottleneck (Collibra, Alation, Purview), you're 90% on one platform (Unity, Horizon, Knowledge Catalog), or you want agent-ready context as SaaS (Atlan).

In practice the pattern emerging in large enterprises is layered: engine-native catalogs (Unity, Horizon) govern their own platform; a federated catalog (DataHub, OpenMetadata, Atlan, Purview) sits above them as the cross-estate context graph; and OpenLineage carries pipeline events between the layers. The "one catalog to rule them all" procurement is giving way to a metadata architecture.

06Evidence from production

Real use cases from industry leaders

LinkedIn — the origin at extreme scale

DataHub (internal) · social platform

LinkedIn built DataHub to catalog millions of datasets, jobs, and features after its crawl-based predecessor (WhereHows) couldn't stay fresh. The push-based, event-driven design — sources emit metadata change events rather than being scraped — became the architectural template the whole category now follows.

At sufficient scale, metadata must be streamed, not crawled. Freshness is the product.

Block — DataHub MCP powering AI agents

DataHub Cloud + MCP · fintech (Square, Cash App)

Block wired DataHub's MCP server into its internal agent stack (home of the open-source "goose" agent), so agents resolve which datasets exist, what columns mean, and what lineage implies before generating SQL or answers. The catalog acts as the agents' ground truth about the data estate.

The first production pattern for "agents + catalog" is exactly the context-platform thesis, running today in a regulated fintech.

Netflix — self-serve metadata workflows

DataHub · streaming media

Netflix uses DataHub to let teams define and manage their own metadata through self-serve workflows — decentralized ownership with central governance, replacing bespoke internal tools (its earlier Metacat served federated technical metadata; DataHub adds the semantic and governance layer).

Winning catalogs are operated as products with self-serve workflows, not curated by a central librarian team.

Saxo Bank — data mesh on DataHub

DataHub + Great Expectations · investment banking

Saxo adopted DataHub as the backbone of a data-mesh operating model: domains publish data as products with owners, glossary terms, and quality checks (Great Expectations) attached. Saxo contributed business-glossary capabilities upstream — a bank co-developing its catalog in the open.

In a mesh, the catalog is the marketplace where domains publish products — and regulated firms can still build in public.

Lyft & Uber — the cautionary parallel

Amundsen · Databook · ride-hailing

Lyft's Amundsen (usage-ranked, "Google-like" data search) and Uber's internal Databook solved discovery brilliantly for their era — Amundsen was the most-adopted OSS catalog circa 2020. But discovery-only scope left no path to governance, quality, or AI context, and Amundsen's community roadmap has effectively ended; Databook's authors went on to found OpenMetadata.

Search alone is a feature, not a platform. The category consolidated around tools that own the full context graph.

Microsoft — governing its own estate with Purview

Purview Unified Catalog · ~half-million employees & vendors

Microsoft's internal digital team runs Purview Unified Catalog over its enterprise data estate: governance domains, curated data products, and health controls give executives measurable data-quality and compliance posture — the same catalog now extended to police what Copilots and agents can access.

Catalog KPIs (curation coverage, quality scores, access hygiene) are becoming board-level AI-readiness metrics.

07Where this lands

Outlook 2026 → 2028 and recommendations

Five predictions

  1. "Catalog" disappears as a category name. DataHub, OpenMetadata, Atlan, and Google have already rebranded around context. By 2028, buying a "data catalog" will mean buying a context platform whose primary consumers are agents, with the human UI as one client.
  2. MCP (or a successor) becomes table stakes, and differentiation moves up-stack: trust scoring, context ranking, and policy-aware retrieval — which context an agent gets, not whether it can connect.
  3. Lineage expands to AI assets. Prompt → model → agent → answer joins source → table → dashboard in the same graph, driven by AI-act-style regulation and internal model-risk teams. Expect OpenLineage extensions for agent/LLM events.
  4. The OSS duopoly consolidates. DataHub and OpenMetadata absorb the remaining OSS mindshare (Atlas and Amundsen fade to legacy), while both monetize AI features through their clouds — keeping healthy pressure on Collibra/Alation pricing.
  5. Layered metadata architectures become the default: engine-native catalogs below, one federated context graph above, standards (Iceberg REST, OpenLineage, MCP) as the seams.

Practical guidance

  • Single-platform shop (mostly Databricks / Snowflake / GCP / Microsoft): use the native catalog (Unity / Horizon / Knowledge Catalog / Purview) — the built-in AI integration and zero-ETL governance beat anything bolted on.
  • Heterogeneous estate, strong engineering: DataHub if lineage depth, real-time metadata, and agent integration lead your requirements; OpenMetadata if breadth-plus-simplicity and built-in quality checks do. Pilot both — a two-week Docker/K8s spike per tool answers most questions.
  • Governance-led, steward-heavy organization: Atlan (agent-forward) or Collibra/Alation (workflow-deep), with OSS as leverage in the negotiation.
  • Whatever you choose: instrument pipelines with OpenLineage now, demand an MCP interface in every RFP, and treat metadata freshness as an SLO — the AI era punishes stale context faster than missing context.
